feat(ui): real dashboard analytics, dark-mode charts and modern polish

The dashboards were rendering invented numbers and ignoring the theme. Both are
fixed, along with the touch-target and empty-space issues found in the UI review.

Dashboard truthfulness
- the three charts were bound to hard-coded module constants (fake weekly
  totals, a painted 77.8% donut, a literal "4m 18s") and /api/dashboard had a
  fallback that returned fabricated KPIs (30 staff, 38 vehicles, 93.3%...).
  Both now use real data; the fallback returns null metrics with
  status:"unavailable" so the UI shows an em dash instead of a lie.
- new lib/analytics/dashboard-series.ts builds real series from
  vehicle_search_events + parking_alerts: 24 hourly buckets for today, 7/30
  daily buckets otherwise, hour-of-day activity and resolution-speed buckets
  with a true average, all bucketed in Asia/Qatar.
- GET /api/dashboard now accepts ?range=today|week|month; the range selector
  was a dead control that never reached the API and now drives KPIs + charts,
  with labels that follow the window.
- chart palette resolves from the active theme instead of hard-coded light
  colours that produced white gridlines on the dark surface.
- honest empty/loading states per chart, plus a notice when the 20k row cap is
  hit. New tests: tests/unit/dashboard-series.test.ts (16) -> 132 total.

Modern polish
- touch targets: language toggle 30->44px, theme toggle 36->44px, admin mobile
  nav 28->44px, "Open Admin Menu" and drawer close ->44px.
- search CTA: disabled state is a readable neutral control instead of a
  50%-opacity maroon button that looked broken.
- device-local recent searches on the home screen (44px chips + clear all).
- admin lists use the existing TableSkeleton instead of a spinner + text.

Verified: tsc clean, lint 0 errors, vitest 132/132, Playwright 44/44
(includes 16 axe specs), dashboard verified against the real local stack
(19 searches today / 136 this week, 24/7/30 buckets, zero console errors).
